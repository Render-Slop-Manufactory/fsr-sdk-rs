# D023 — Explicit and automatic exposure

- Date: 2026-10-14.
- Status: **accepted** under explicit maintainer authorization to implement M13
  after checking for blockers. The deferred native batch subsequently passed on 2026-10-15.
- Scope: SDK v2.3.0, current fixed DX12 resource/profile and both ownership families.
- Relationship: extends D008/D011's explicit-only profile, D012 options and D018
  provider requirements; preserves D020 pre-exposure and D016 direct controls.

**Extension, 2026-10-15:** [D025](D025.md) queries requirements for every
context, permits supported required masks at creation and validates their presence
at dispatch. The original automatic-only query/rejection choice below is retained
as the prior contract; exposure mode and mapping remain unchanged.

## Decision

Add portable, non-exhaustive `ExposureMode::{Explicit, Automatic}` and
`UpscalerOptions::{exposure_mode,set_exposure_mode}`. Explicit remains the default.
Automatic adds `FFX_UPSCALE_ENABLE_AUTO_EXPOSURE` (`1 << 5`) to the same private
flag conversion used by creation and pre-create memory estimation. Exposure mode
is fixed at creation; source options cannot reconfigure existing contexts.

Keep `UpscaleResources::new(color,depth,motion,exposure,output)` unchanged. Add
`without_exposure(color,depth,motion,output)` for automatic contexts. The private
exposure borrow becomes optional; `exposure()` returns the actual borrow or None.
Dispatch requires a texture in explicit mode and absence in automatic mode.
Mismatch returns `DispatchValidation::ExposureMode` before COM inspection/native
recording, without poisoning the context. Automatic descriptors supply a null
exposure resource with all metadata/state fields zero. Only present resources
participate in identity, extent, format and device checks or GPU lifetime duties.
The explicit 1×1 R32F validation and all other formats/extents stay unchanged.

Automatic creation performs one live `resource_requirements` query on the actual
selected provider before returning a usable context. Required colour/depth/motion
inputs fit the profile; the exposure bit is satisfied by the automatic creation
flag, as specified by the header. Required masks or unknown required bits reject
construction with `Error::UnsupportedResourceRequirements { required }`, retaining
the complete mask. Optional and overlapping bits are not used to invent extra
requirements. This is a resource-contract check, not a general capability query
or proof that a provider implements the flag correctly.

Query errors preserve native `Operation::Query` codes. A post-create rejection
makes the ordinary single terminal cleanup attempt with no wrapper GPU recording
or submission. Successful cleanup releases dependencies; failed cleanup retains
its critical bundle under D005, without retry. The original query/profile error
is returned. Explicit creation performs no additional query and preserves its
original behaviour. Both families share construction, checks and descriptor mapping.

## Safety and limits

The trusted provider must support the selected automatic flag and absent exposure
through creation, estimation, dispatch and teardown under the existing unsafe
acquisition/dispatch contracts. The existing query non-retention, numerical,
serialization, GPU-state and ordinary-error assumptions cover the construction
query. No new thread, callback or resource ownership claim is made.

`PreExposure` remains a separate positive finite factor already applied to colour;
it is forwarded unchanged in either mode. Automatic exposure neither enables HDR
nor supplies an exposure texture/value to the application's tonemapping pipeline.
The renderer retains responsibility for scene content, states, backing storage,
submission and GPU completion. No image-quality guarantee, calibration or policy
is introduced. Quality validation remains held. Bounded native integration passed
on the [recorded Windows configuration](../release/2026-10-15-windows-m11-m14-verification.md).
No new dependencies, SDK pin, platform or release publication is selected.

## Verification and basis

Portable tests cover default/clone/traits, creation-estimate flags `32` and combined
`62`, and acceptance/rejection of required masks. Paired raw Rust/C++ assertions
check bit 5. Windows fixtures exercise both families' creation query, exact null
exposure metadata, explicit mapping, unchanged pre-exposure, skipped inspection of
an omitted invalid resource, mismatches without native entry, valid retry and
terminal cleanup after unsupported requirements or native query errors.

A prepared three-frame automatic native case reuses existing moving/jittered
DX12 equipment, real provider requirements/memory queries, submission/fencing,
finite/written output, device/debug checks and explicit teardown. It is selected
for source and artefact native profiles with an infrastructure regression. The
helper still owns an unused exposure allocation, but the automatic frame never
supplies it to FSR; this case makes no renderer-allocation saving claim. The native
case uses the local family; movable mapping/cleanup is covered by controlled
fixtures. [Windows fixture/MSRV/C++ ABI and native execution](../release/2026-10-15-windows-m11-m14-verification.md)
pass on one configuration. The [earlier implementation record](../release/2026-10-14-automatic-exposure-verification.md)
retains the original CI failure and correction.
