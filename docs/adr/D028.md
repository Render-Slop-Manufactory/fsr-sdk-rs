## Public-shape replacement selected — 2026-10-26

[D042](D042.md) supersedes provider storage in creation options and paired flat
setup queries with one setup-bound selection through planning and creation. It
also selects public provider-data construction without weakening fresh native
membership or live-identity checks. U07/U10/U12 remain open; the complete trust
redistribution requires U07's audit. The implemented baseline and earlier
evidence below are retained, including no fallback and external coordination.

## Problem

Enumeration and live provider metadata exist, but creation and pre-create
queries cannot request an enumerated provider. The runtime/context layers also
lack Configure forwarding, and resource requirements have no pre-create route.
The next features need the same explicit provider across those operations.

## Naming amendment — 2026-10-18

The maintainer authorized `render_size_for_quality` terminology across both
ownership families and the default/explicit runtime routes, making clear that
these queries calculate provider-reported quality-mode dimensions rather than
read the context's current active size. Only unreleased method names change;
routing, validation, results and native contracts are unchanged.

## Public API

Keep portable `ProviderId` opaque, `Copy`, comparable and hashable, with no
numeric constructor/accessor, version interpretation or capability guarantee.
Use `Option<ProviderId>` for selection; `None` keeps the SDK's then-default route.
No numeric sentinel represents default selection.

| Owner | Addition or behaviour |
|---|---|
| `UpscalerOptions` | `provider() -> Option<ProviderId>` and `set_provider(Option<ProviderId>)`; constructor defaults to `None` |
| Both upscaler constructors | Read selection from options; keep existing signatures |
| Both runtime memory-estimate methods | Read selection from options; keep existing signatures |
| Both runtime families | `upscaler_resource_requirements_dx12(device, provider: Option<ProviderId>) -> Result<ResourceRequirements, Error>` |
| Both runtime families | Add the four explicit-provider utility variants below; keep existing default-provider methods unchanged |
| Both live upscaler families | Existing queries continue to use the context's actual provider; no per-query provider override |

The utility additions are ordinary `&mut self` methods with the same checked
inputs/results and gates as their default counterparts:

```text
upscaler_ratio_for_provider_dx12(device, provider: ProviderId, mode)
upscaler_render_size_for_quality_for_provider_dx12(device, provider: ProviderId, display, mode)
upscaler_jitter_phase_count_for_provider_dx12(device, provider: ProviderId, render, display)
upscaler_jitter_offset_for_provider_dx12(device, provider: ProviderId, index, phase_count)
```

Existing constructors and default utility queries retain their behaviour.
Options store a requested ID, not a native handle or device/runtime reference.
Public documentation must require the same provider selection for related
pre-create queries and subsequent context creation. Existing default utility
methods do not read `UpscalerOptions` or inherit its selection: callers selecting
an explicit provider must pass that same ID to the explicit-provider utilities
and resource query, and use matching options for memory estimation and creation.
Live-context queries already use the context's actual provider.

The new resource query reports provider masks; it does not accept/reject the
wrapper's complete dispatch profile or reserve resources. In particular, do not
apply the context's supported-required-input filter to this informational query.

## Selection validation and native identity

For every explicit pre-create query and context creation:

1. Perform applicable pure input checks first. Under the caller's common native
   coordination, enumerate using the actual runtime and supplied DX12 device.
2. Require the requested ID in that fresh bounded observation. Otherwise return
   `Error::ProviderNotEnumerated { requested: ProviderId }` without
   entering the selected creation/query operation. Enumeration itself may have
   made native calls; preserve its errors as `Operation::Query`.
3. Attach `ffxOverrideVersion`; forward exactly that ID. Never retry using the
   default or infer a replacement from names, numerical ordering or query masks.
4. After successful explicit creation, query effective live identity before
   checking/storing resource requirements. A different ID returns
   `InvariantViolation::ProviderSelectionMismatch { requested, actual }` through
   `Error::NativeInvariantViolation`. Do not return that context to the caller.

The existing owner performs its normal terminal cleanup if identity, requirements
or subsequent construction checks fail, retaining dependencies on destroy failure.
Preserve native query errors and existing invalid-name/zero-live-ID checks.
Default creation adds no identity query solely for this feature. Neither route
changes the selected provider of a live context.

Fresh enumeration is a membership check, not a reservation or a stable identity
certificate. D018's count/fill operation can truncate or miss concurrent changes.
An absent ID means not observed, not a proven wrong-device/stale-ID diagnosis.
Do not claim to detect reuse of an identical native ID or changes after the
observation. Native refusal remains possible and preserves its exact code.
Pre-create queries have no effective-provider output: they cannot independently
verify that a closed provider honoured the override.

## Raw ABI, chains and lifetime

Bind `FFX_API_DESC_TYPE_OVERRIDE_VERSION` (5) and `ffxOverrideVersion` exactly:
the common header followed by `versionId: u64`. Keep the mandatory upscaler API
version node at 4.1.1, independently of provider choice.

Use concrete private chain storage, formed at final addresses before linking:

| Invocation | Chain with explicit selection |
|---|---|
| Creation | root → API version → DX12 backend → provider override |
| Pre-create utility/resource requirements | query root → DX12 backend → provider override |
| V2 memory estimate | query root with device field → provider override |
| Enumeration | Existing descriptor with its device field; no override |

Omit the override node for default selection. Preserve existing default chain
shapes, including memory V2's direct device field. Every device occurrence must
refer to the same supplied device. Creation nodes remain address-stable and owned
through terminal teardown or exceptional retention; never relink them afterward.
Pre-create query nodes/outputs are temporary and live for the synchronous call;
restore any borrowed header links on return. No public generic chain API or
runtime-global provider setting is introduced.

## Native trust and synchronization

**Accepted contract:** keep query and construction methods safe under
D018/D022's acquisition model. Put all provider-specific native-trust obligations
of this decision in the `# Safety`
contracts of both `Runtime::load_unchecked` and `MovableRuntime::load_unchecked`.
They cover every default or explicitly selected provider actually used, including
the new pre-create resource route and override chains:

- Safely process valid selected requests and either honour the override or
  return an ordinary native error; no silent default substitution is assumed.
- Consume temporary pre-create chains, devices and output storage synchronously
  without retention, with existing name/output validity and numerical guarantees.
- Preserve D018 live-query GPU-state compatibility and ordinary-query-error
  continuation. Resource queries and selection do not wait for GPU completion.
- Apply D013's common-domain serialization/non-reentrancy and destination-thread
  obligations to all selected-provider calls and cleanup.

Enumeration and effective live identity do not prove those native properties.
They remain caller-established native trust, not an AMD guarantee inferred from
fixtures. This accepted acquisition-contract extension belongs to unreleased
0.3.0; its implementation and verification remain separate work.
No safe public Configure operation is covered by this trust extension.

## Internal Configure seam

Add private unsafe `RuntimeState::configure(context, desc)` and owner forwarding
using the existing const-descriptor signature and unmodified native return code.
Null context selects global configuration; a live owner supplies its own handle.
Keep descriptor interpretation and higher-level eligibility outside this seam.
Existing dispatch/query poison and terminal destruction behaviour stay unchanged.

This package adds no public key/pointer escape hatch, Configure controls, global
diagnostic mutation or callback registration. Consequently it does not decide
Configure numerical policy, GPU-idleness, pointer retention or native-error
continuation. The five typed controls and their public errors belong to the next
contract; an OK return must not be presented as proof that a provider applied it.

## Alternatives

- A runtime/device-bound selection token would add ownership, trait and lifetime
  machinery without proving native identity stability. Prefer the existing
  opaque ID plus fresh observation and explicit limits.
- A runtime-global selection would hide shared mutable policy and affect sibling
  operations. Keep selection in options or explicit query arguments.
- Adding a provider argument to existing utility signatures would break current
  source consumers. The explicit variants preserve those call sites.
- Call-specific unsafe selected queries could avoid extending acquisition trust.
  Not selected: the maintainer accepted the existing conditional safe surface
  with explicit acquisition obligations. Do not add both interfaces without a
  concrete need.

## Verification and implementation order

The implementation order is raw override ABI, shared selection/chain
logic, public options and query methods, then the private Configure seam.
Keep shared behaviour in the existing runtime/core seams for both families.

1. Paired Rust/C++ Windows x64/MSVC assertions for override tag, field types,
   offsets, size and alignment; verify const Configure pointer forwarding.
2. Controlled fixtures for default/selected chains, actual device routing,
   missing IDs, enumeration failures, invalid-input ordering, exact errors,
   effective-provider mismatch and terminal dependency retention. Propagate
   wrapper selection failures without fabricating a native return code.
3. Both-family public consumers, portable ID/options availability, trait/gate
   checks, existing default queries and construction regression, stable/MSRV.
4. Targeted Windows native enumeration → explicit selection → pre-create
   utilities/memory/resources → creation → effective live identity and existing
   dispatch/cleanup controls. Test default separately; do not assume multiple
   providers are available or optional features supported on every provider.

Compilation, controlled execution, ABI and actual native/GPU checks are separate
results. Final archive checks remain in the release checklist. This decision
does not complete R04/U02 or change provider/platform support claims.
