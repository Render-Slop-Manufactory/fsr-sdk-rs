## Decision

Expose portable, non-exhaustive enums:

- `DepthConvention::{StandardFinite, ReversedFinite, StandardInfinite, ReversedInfinite}`.
- `MotionVectorResolution::{Render, Display}`.
- `MotionVectorJitter::{Excluded, Included}`.
- `MotionVectorUnits::{Uv, Pixels}`.

Defaults preserve standard finite depth and render-resolution, jitter-free UV
motion. The context's options select depth, motion resolution and jitter inclusion
before creation. A single private conversion combines native depth-inverted
(`1 << 3`), depth-infinite (`1 << 4`), display-motion (`1 << 1`) and
jitter-cancellation (`1 << 2`) bits for both creation and pre-create memory
estimation. Source options cannot reconfigure an existing context.

`CameraParameters::new` retains positive finite geometric distances with
`near < far`; reversed depth does not swap them. `new_infinite(near, fov, metres)`
checks positive finite near/metres and finite FOV strictly between zero and pi,
marks the infinite projection explicitly and supplies `f32::MAX` as the native
far placeholder, following the pinned SDK sample. IEEE infinity remains rejected
by the finite constructor. `has_infinite_far_plane()` distinguishes an infinite
camera from a finite camera whose far happens to be `f32::MAX`. Dispatch rejects
finite/infinite camera-context mismatches with
`DispatchValidation::CameraDepthConvention` before COM inspection/native entry,
without poisoning the context. Infinite near/FOV/metre checks do not establish a
complete provider-safe numerical domain.

Motion resources remain RG16F current-to-previous displacement, +X right/+Y down.
Their extent must equal the selected render or output size; colour/depth remain
render-sized. UV scale uses the motion texture's width/height, while pixel units
use `(1, 1)` and pixels of that texture. Units are selected per frame through
`set_motion_vector_units`. The wrapper never rewrites texture content.

Excluded jitter requires jitter-free vectors; Included requests native
cancellation of projection jitter already present in vectors. Applied projection
jitter remains reported in pixels, unchanged. Depth content, camera projection,
motion resolution/units/jitter content must match the selected profile. Contents,
resource states, provider numerical limits, GPU lifetimes, error and cleanup
obligations stay at the existing unsafe boundaries. No HDR, automatic exposure,
dynamic active extents or quality policy is introduced. NDC/axis/direction
conversions and arbitrary scales remain deferred.

## Verification and evidence

Portable checks cover defaults, clone independence, camera domains and explicit
infinite identity. Host query tests cover all 16 context flag combinations.
Controlled Windows fixtures cover every context combination and both units for
both ownership families, unchanged camera/jitter/scalars, reference counts,
wrong-camera/wrong-motion-extent rejection, no native entry on rejection and
successful retry. Paired Rust/C++ assertions cover the four selected raw bits.
Eight representative native profiles each record three jittered moving frames,
with correct texture allocation, pending depth/motion uploads, memory query,
submission/fences, finite/written output, device/debug checks and explicit teardown.
No image-quality comparison is required.
[Windows fixture/MSRV/ABI and eight native profiles](../release/2026-10-15-windows-m11-m14-verification.md)
pass on one configuration, following the
[implementation checks](../release/2026-10-14-depth-motion-profiles-verification.md). The
[first-slice record](../release/2026-10-14-depth-motion-verification.md) retains
its earlier, narrower evidence.
