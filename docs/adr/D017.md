# D017 — Explicit pinned maintainer SDK acquisition

- Recorded: 2026-10-12
- Status: accepted — maintainer approved the reviewed R02 scope and trust limits

**Context:** Native verification previously required a manually supplied SDK.
D002 pins v2.3.0 and D007 keeps runtime acquisition application-controlled. The
[source record](../research/records/2026-10-12-src-fidelityfx-sdk-acquisition.md)
proposed a separate developer bootstrap without proving archive contents.

**Choice:** `tools/verification/sdk.py`, reached only by explicit `run.py sdk`
commands, acquires the official v2.3.0 prebuilt ZIP using a fixed archive digest.
It installs two existing hash-pinned DX12 DLLs, four pinned headers and full AMD
licence/third-party notices under `external/FidelityFX-SDK/v2.3.0/`. The ZIP has no
headers or notices: those six files come from the full D002 commit, with local
source-tree input available for offline installation. Every installed payload
file has a project-controlled digest; provenance is never its own trust anchor.
Existing installations are rechecked and never repaired or overwritten implicitly.

`sdk verify` is offline and checks file identity/inventory. `--strict` additionally
requires Windows Authenticode, publisher, timestamp and online revocation-policy
verification. It uses PowerShell, Windows SDK SignTool and the OS chain builder;
there is no project trust store, certificate parser or revocation service. Unknown
or unavailable checks reject strict acceptance. Current-clock chain checks may
conservatively reject expired certificates despite a valid historical timestamp.
Ordinary install reports unavailable signature checks honestly; executed signature
failures reject installation. Native profiles retain their existing requirements.

**Consequences:** No Cargo or published-crate download, automatic runtime choice,
global DLL registration, additional verification profile or redistribution.
Downloaded files remain ignored local inputs. Whole-archive SHA-256 is checked
before bounded allowlist extraction and staged same-filesystem publication.
Sibling locking serializes this tool; parents must be caller-controlled.
Selected files retain AMD's MIT exceptions and complete notices; the project's
MPL-2.0 licence does not relicense the mixed-term SDK.

**Evidence and limits:** The earlier [implementation verification](../release/2026-10-12-sdk-acquisition-verification.md)
records actual ZIP/source downloads, inventory/include audit, matching DLL digests,
online/local installation and portable failure tests. At that stage, real Windows
trust, native compilation/execution and dependency closure were unperformed.
Acquisition success establishes no new platform/GPU support.
The subsequent [Windows verification](../release/2026-10-12-windows-m10-sdk-verification.md)
completed real strict trust checks and native execution from the acquired subset;
broader runtime dependency/deployment closure remains unverified.
