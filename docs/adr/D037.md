# D037 — D32 and D32S8 depth-buffer allocations

- Date: 2026-10-22.
- Status: **accepted** under the maintainer's instruction to implement the next
  D32 depth-buffer family after D035. Implementation and verification are
  separate checkpoints below.
- Scope: U05, development `fsr-sdk 0.3.0` / `fsr-sdk-sys 0.1.2` under
  [amended D031](D031.md), pinned SDK
  v2.3.0, Windows x64/MSVC + DX12, both ownership families.
- Extends [D011](D011.md)/[D035](D035.md)'s depth profile without changing
  borrowed-resource APIs, allocations, active-region policy or ownership.

## Choice and exact mappings

Renderers can pass their shader-readable D32 depth buffer directly. Read the
actual allocation from `GetDesc`; expose no view override, copy or conversion.
The depth role additionally accepts these single-mip/slice/sample Texture2D
allocations at the existing maximum render extent:

| Actual allocation | DSV interpretation | Backend depth SRV, plane 0 | Native surface value | Native usage |
|---|---|---|---|---|
| `R32_TYPELESS` | `D32_FLOAT` | `R32_FLOAT` | `R32_TYPELESS` (37) | `READ_ONLY` (0) |
| `D32_FLOAT` | `D32_FLOAT` | `R32_FLOAT` | `R32_FLOAT` (28) | `DEPTHTARGET` (4) |
| `R32G8X24_TYPELESS` | `D32_FLOAT_S8X24_UINT` | `R32_FLOAT_X8X24_TYPELESS` | `R32_FLOAT` (28) | `READ_ONLY` (0) |
| `D32_FLOAT_S8X24_UINT` | `D32_FLOAT_S8X24_UINT` | `R32_FLOAT_X8X24_TYPELESS` | `R32_FLOAT` (28) | `DEPTHTARGET | STENCILTARGET` (36) |

Native mappings and usage exactly follow the pinned
[public DX12 helper](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/60f4ea81909200d8542eca14dccb2628b763a9a3/Kits/FidelityFX/api/include/dx12/ffx_api_dx12.h).
Add only raw surface `R32_TYPELESS = 37` and usage `DEPTHTARGET = 4` /
`STENCILTARGET = 32`, with independent Rust and pinned-header C++ assertions.
Layouts, dependencies and SDK acquisition remain unchanged.

The pinned [generic DX12 backend](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/60f4ea81909200d8542eca14dccb2628b763a9a3/Kits/FidelityFX/backend/dx12/ffx_dx12.cpp#L1904-L2163)
reconstructs the SRV from the actual allocation; a native `R32_FLOAT` enum alone
cannot describe the 64-bit depth/stencil family. Retain the allocation format
privately through inspection so device checks select the actual depth view.
This source is a mapping basis, not proof about every supplied provider binary.

All four routes require `ALLOW_DEPTH_STENCIL`, no `DENY_SHADER_RESOURCE` and
no `ALLOW_UNORDERED_ACCESS`. This selects depth-buffer access, not arbitrary
typeless scalar colour or motion reinterpretation. D16, D24, stencil-only and
view-only formats remain outside the profile. Existing R32F/R16F depth and
other roles retain their contracts and query behaviour.

## Device checks and errors

After canonical device membership and metadata checks, inspect the depth role
in the existing fixed order. For each route query the DSV for `TEXTURE2D |
DEPTH_STENCIL`, then the exact SRV for `TEXTURE2D | SHADER_LOAD | SHADER_SAMPLE`.
Do not require UAV views or typed load/store bits for these depth inputs.

For typed `D32_FLOAT` and `D32_FLOAT_S8X24_UINT`, first query
`D3D12_FEATURE_D3D12_OPTIONS3` and require
`CastingFullyTypedFormatSupported`. Microsoft's
[relaxed-casting specification](https://microsoft.github.io/DirectX-Specs/d3d/RelaxedCasting.html)
defines that capability; it cannot be inferred from an ordinary format-support
query. Typeless routes need no fully typed casting query. The
[planar depth/stencil specification](https://microsoft.github.io/DirectX-Specs/d3d/PlanarDepthStencilDDISpec.html)
defines the depth-plane SRV and separate stencil plane.

Missing view/casting support reports `Depth` / `FormatSupport`. A missing
depth/stencil flag reports the added `ResourceProperty::DepthStencil`;
UAV-capable depth reports `UnorderedAccess`, whose documentation now covers
this invalid capability as well as missing output capability.
Failed device queries preserve the exact HRESULT with
`ContextDeviceForResource(Depth)` and `CheckFormatSupport`, or the added
`InspectionOperation::CheckFormatCasting` for OPTIONS3. No failed check enters
FidelityFX or poisons a usable context. Optional preflight and recording share
this path; recording repeats all checks. There is no persistent capability cache.

## Renderer and provider obligations

Depth contains standard/reversed, finite/infinite device depth matching the
context and camera. Stencil is not an upscaling input. The caller owns DSV
production, depth/stencil synchronization, resource transitions and all GPU
lifetimes. Before dispatch, transition the whole supplied resource, including
both planes of D32S8, to `NON_PIXEL_SHADER_RESOURCE`; the descriptor declares
the whole resource `COMPUTE_READ`. This API does not support retaining a
separately writable stencil plane during dispatch. Restore renderer states
explicitly after the provider's work and required synchronization.

Device bits certify neither provider support nor safe native accesses. The
existing unsafe dispatch/provider-trust contract, whole-output write allowance
and terminal native-failure policy remain. No provider fallback, format selector,
DSV handle, implicit barrier or resource retention is added.

## Verification contract

- Both-family controlled tests cover exact format/usage/state, the two view
  queries, conditional casting checks, missing bits/flags, exact query HRESULTs,
  wrong roles, foreign devices, retry and balanced references. Existing shape,
  extent, alias, poison and native-failure regressions remain applicable.
- Stable CI, Rust 1.88.0/MSRV, public consumers and independent MSVC ABI checks
  cover the changed declarations, diagnostics and documentation.
- The opt-in `native-depth-formats` profile uses renderer-style DSV clears to
  produce two distinct depth values and a distinct stencil value. An independent
  compute shader reads the exact backend SRV into fenced CPU readback. Copy
  readbacks additionally audit the depth and stencil planes after upscaling.
- Both public owners and a separate pinned-header C++ context/descriptor path
  run on selected 4.1.1 and 3.1.5. Standard/reversed depth and active-render/output
  shrink/grow cover all four routes. Require complete finite output writes,
  clean ordinary diagnostics, selected identity, explicit cleanup, exact same-
  format public/C++ output equality and matched R32F baseline equality for fixed
  geometry. Changed-colour and no-dispatch controls remain mandatory.
- The [protocol](../../tools/verification/depth-formats-protocol.md) freezes these
  criteria. A failed capability, native call, write, sample or reference result
  cannot be reclassified as support. No image-quality, performance or GBV gate
  is selected; final extracted-package verification remains separate.

## Checkpoint

Implemented for both ownership families. [Verification](../release/2026-10-22-depth-format-verification.md)
passes 178 stable CI, 155 Rust 1.88.0/MSRV and 82 native cases with unchanged
inputs. Exact depth samples, preserved stencil, public/C++ output and matched
R32F baselines pass on the recorded 4.1.1/3.1.5 configuration. Earlier compilation,
fixture and input-integrity failures remain recorded. D16/D24, BGRA/sRGB and other remaining U05
families are not accepted by this decision. U05 completion and release readiness
do not follow from this slice.
