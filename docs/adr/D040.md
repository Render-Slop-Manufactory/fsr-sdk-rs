## Decision

Keep ordinary debug settings as typed values. Add a separate unsafe constructor
for native callbacks, and explicit unsafe methods for global diagnostics.
The wrapper owns descriptor storage, context teardown and compatible host-table
forwarding. The integration owns callback targets, their state and allocator
policy for their full native reachability, including uses beyond a context.

Do not add captured closures, an allocator trait, per-context callback registry,
TLS routing, a registration guard, implicit unregister, a renderer allocator or
a new dependency. These would need identities and shutdown guarantees that the
SDK does not supply. Explicit unsafe access remains part of `fsr-sdk`; consumers
need not reconstruct the context chain or abandon the existing owned upscaler.

## Why this boundary

| Evidence | Contract consequence |
|---|---|
| Both tested providers use later resource/CB callbacks for surviving contexts, including cross-set frees. | Allocation compatibility is a lasting shared-state obligation. An allocation callback argument is not a per-context allocator assignment. |
| Omitted/incomplete DX12 sets do not reset prior registration. | Optional callback groups mean no new registration for that group; there is no restore-default operation in the constructor. |
| 3.1.5 invokes a message callback after its installing context is destroyed. | A context's successful Drop cannot authorize reclaiming message targets. |
| 4.1.1 warning routing follows explicit global configuration despite later creation pointers; modern global controls reach both providers. | Keep creation messages and global configuration as separate public operations. Promise neither identical provider behaviour nor per-context routing. |
| Signed-loader effect/deprecated-route handling differs from inspected open code. | Preserve the effect in modern forwarding and return native refusal unchanged; do not implement provider allow-lists or automatic legacy fallback. |
| Win64 CB return exchange passes current/MSRV fixtures; heap invocation is unobserved. | Use the exact by-value ABI. Bind all five callback roles, while keeping the heap native-evidence limit explicit. |

## Ordinary configuration

Add portable `UpscalerOptions` getters/setters:

```text
debug_checking() -> bool
set_debug_checking(bool)
debug_visualization() -> bool
set_debug_visualization(bool)
```

Both default to false. The existing shared flag mapper supplies checking bit 7
and visualization bit 9 to creation and memory V2. Use the same complete options,
device and provider selection for related memory estimates and creation.
These are native requests, not a validator guarantee or accurate memory reservation.
Neither setting installs a message callback or sets the global output filter.

Add `UpscaleDispatch::draw_debug_view() -> bool` and
`set_draw_debug_view(bool)`, default false, mapping only native dispatch bit 0.
Preserve existing colour/hint bits. The setting neither changes creation options
nor resets history. It can change the output through the SDK's debug overlay.

Forward the three controls independently. Do not reject a frame solely because
draw-debug-view is true while creation visualization is false: a universal native
dependency is not established. Unsafe dispatch must establish actual-provider
compatibility for the requested debug combination, just as for other provider
controls. Document enabling visualization at creation as the intended native
permission for debug resources, without inventing a capability query or fallback.
Metadata preflight cannot certify debug output or actual-provider support.

Add portable `DebugLevel::{Silent, Errors, Warnings, Verbose}`, mapping exactly
to `0`, `1`, `2`, `0x0fffffff`. This level configures global message output,
independently of checking/visualization. No arbitrary numeric debug-level escape
is needed in the ordinary API; faithful raw declarations remain in sys.

## Callback configuration and public compatibility

Add Windows/DX12-gated `upscaler::dx12::interop`. This is the explicit unsafe
native-integration boundary permitted by [scope](../../SCOPE.md#public-api-surface).
It contains callback aliases and callback-table value types; ordinary portable
options and root upscaler imports gain no raw pointers, function pointers or chains.

Provide `interop::abi` reexports sufficient to implement the native callbacks
using only the `fsr-sdk` dependency. Reuse the authoritative sys declarations
and preserve exact C signatures, integer widths, pointer constness and the CB
return type. Native callback signatures use raw COM interface pointers, never
owned Rust `ID3D12Resource`/`ID3D12Heap` wrappers by value. The existing Windows
0.62 compatibility boundary applies to renderer COM conversions. Any necessary
raw Microsoft-type representation is subject to independent ABI checks; this
proposal selects no new dependency or duplicated Rust ownership implementation.

All callback aliases denote non-null `unsafe extern "C" fn` values with the
individual native signatures. Nullable fields are represented by `Option` of
that alias. In particular, `MessageCallback` takes `(u32, *const u16)`;
unknown severities remain representable. The CB callback takes payload pointer
and `u64` byte count and returns the aggregate **by value**, not an explicit
output-pointer approximation.

The callback-table types have private fields and the following pure assembly API.
These constructors/setters make no native call and grant no registration or
lifetime guarantee; installation happens only at the unsafe operations below.

| Type | Construction and mutation |
|---|---|
| `HostAllocationCallbacks` | `new(user_data, allocate, deallocate)`, with a raw userdata pointer and two non-null host callback aliases |
| `ResourceAllocationCallbacks` | `new(allocate, deallocate)`, both non-null resource aliases |
| `HeapAllocationCallbacks` | `new(allocate, deallocate)`, both non-null heap aliases |
| `Dx12AllocationCallbacks` | Empty `Default`; `set_resources(Option<ResourceAllocationCallbacks>)`, `set_heaps(Option<HeapAllocationCallbacks>)`, `set_constant_buffer_allocator(Option<ConstantBufferAllocator>)` |
| `CreationCallbacks` | Empty `Default`; `set_host_allocator(Option<HostAllocationCallbacks>)`, `set_dx12_allocations(Dx12AllocationCallbacks)`, `set_message_callback(Option<MessageCallback>)` |

The host userdata pointer may be null if its functions support that convention.
Resource/heap pairs are indivisible, preventing accidental incomplete pairs
that the inspected backend silently ignores. All five DX12 functions remain
accessible. Arbitrary malformed/partial native descriptors remain a sys-level
unsafe concern, not an additional high-level mode.

`CreationCallbacks` is neither Copy, Clone, Send nor Sync. It is an assembly
value, not an owner of userdata or a registration guard. Its Drop does not free
userdata, call deallocators, unregister or restore another function pointer.
The other table values similarly own no callback target; no unsafe Send/Sync
implementation is added merely to make pointer-containing configuration movable.

## Callback-bearing construction

Keep existing safe `Upscaler::new` and `MovableUpscaler::new` signatures. Add:

```text
unsafe Upscaler::new_with_callbacks(
    &Runtime, &ID3D12Device, UpscalerOptions, interop::CreationCallbacks
) -> Result<Upscaler, Error>

unsafe MovableUpscaler::new_with_callbacks(
    &MovableRuntime, &ID3D12Device, UpscalerOptions, interop::CreationCallbacks
) -> Result<MovableUpscaler, Error>
```

Consume the callback table, retaining its native values in pinned creation
storage before the first native create. Keep the mandatory API-version node,
backend and optional override, inserting a nonempty DX12 callback node after
the backend and before the override. Retain the separate host callback struct
at a stable address and pass it to both create and destroy. Do not pass a fresh
default allocator to destroy a custom-allocated context. Empty DX12 tables omit
the extension; empty `CreationCallbacks` follows the ordinary constructor path.

Provider enumeration, override validation, post-create identity and requirements
checks retain their existing order and error semantics. The wrapper supplies
no host allocator argument to Query, which has no such native parameter, and
does not attach the creation extension to unrelated pre-create queries.

| Omitted/null choice | Meaning |
|---|---|
| Host table absent | Pass native null host allocator for this create and its destroy. |
| DX12 pair/CB absent | Supply no new callback for that group. Prior module registration may still service this and sibling contexts. |
| Creation message absent | Pass null `fpMessage`. Provider-specific effects on shared message state are not promised; this is not a preserve-previous operation. |
| Global callback null | Forward null to the selected global setter. It establishes no reclamation or quiescence boundary. |

Default construction may therefore encounter previously installed DX12 callbacks
and may affect global messages according to the provider. The unsafe installer's
lasting obligations cover such default constructors and other native users.
The wrapper does not claim that each runtime object defines an isolated module.

## Lasting safety contract

The unsafe callback constructor and diagnostic setters require all of the
following, through later safe calls, unsafe recordings, explicit destruction,
implicit Drop and Rust unwinding:

1. **Valid targets and inputs.** Callback code and all referenced state remain
   valid for every possible native invocation, including creation, queries,
   configuration, dispatch, teardown, errors and later contexts using shared
   registration. Native borrowed descriptor/payload pointers are consumed only
   within their valid invocation window. Callback code in a plugin requires
   independently retained plugin code, not just the FSR runtime handle.
   The actual provider must stop accessing wrapper-owned creation/host-table
   storage before a successful destroy returns. Copied global function pointers
   may remain callable afterwards, but must not depend on that released storage.
   This is an explicit native-lifetime assumption, distinct from requiring all
   callbacks to stop at context destruction.
2. **External ownership.** The integration owns host userdata, allocator maps,
   callback-used device references and no-userdata targets. Retaining the wrapper
   table does not retain those pointees. No short borrowed target may expire
   merely because a constructor returned, a context was destroyed, a function
   pointer was replaced or a Rust runtime handle was dropped. Reclamation needs
   an actual no-active/no-future-use guarantee; process-lifetime state is a valid
   integration strategy. Do not construct a per-context registry from `effectId`.
3. **Shared allocation compatibility.** Every allocation must be freed using a
   compatible implementation and live state, even when the native free callback
   is a later registration. Coordinate all affected contexts and external users.
   Use one compatible allocation domain, or establish that no outstanding native
   allocation or invocation can be affected before installing an incompatible
   replacement. The wrapper supplies no default restoration or exclusivity token.
4. **Threading and reentry.** Preserve D013's common-domain serialization and
   non-reentrancy, including other acquisitions and implicit cleanup. Establish
   actual callback thread compatibility; local ownership does not constrain
   native workers. Do not reenter the affected SDK domain from callbacks. The
   wrapper adds no lock across native callback-capable calls.
   Registration changes must also be compatible with internal native activity;
   an application lock does not prevent a worker racing an unsynchronized native
   callback slot. Establish the necessary absence of overlap or native protection.
5. **No unwinding.** Raw callback bodies must return normally or terminate the
   process; Rust/C++ unwinding must not cross the callback ABI. There is no wrapper
   trampoline and therefore no promised `catch_unwind` or fabricated callback
   `Result`. Copy any valid native UTF-16 message during invocation before storing
   it elsewhere; support null text defensively and do not retain the pointer.
6. **Native failure channels.** Supply valid allocation results whenever the
   actual native consumer continues using them. Host allocations must provide at
   least the requested number of bytes, aligned to hold any native type; host
   deallocation must accept a null memory pointer. A null pointer/error code is a
   recoverable signal only when that consumer safely supports it. Otherwise the
   integration needs a success-or-termination allocation policy. The API neither
   catches native faults nor promises OOM recovery; free return codes and CB's
   missing error channel must retain their actual semantics.
7. **GPU and COM ownership.** Return a usable resource/heap reference with the
   matching deallocator responsible for its release/allocation accounting. Never
   create a second Rust COM owner from a borrowed pointer without owning an AddRef.
   Heap start offsets must satisfy native placement/alignment requirements, and
   free size may be the logical request rather than the aligned heap size. CB
   `data` is payload, not userdata: copy it to suitable durable backing, return
   the required aligned binding handle, and retain storage/allocation ranges
   through GPU completion. A live COM reference alone does not prevent reuse of
   the underlying range. Renderer submission, residency and fences remain external.

The movable constructor additionally requires these dependencies, callbacks and
final cleanup to be compatible with every destination thread allowed by D013.
The movable upscaler remains Send but not Sync only after its concrete fields and
the unsafe constructor contract are audited together. The local upscaler remains
neither Send nor Sync. No callback-bearing trait guarantee follows from the spike's
main-thread observations or from a function-pointer value's auto traits.

## Failure and teardown policy

Keep D005's default no-new-callback path unchanged. For construction supplying
at least one new callback/table, use the following explicit extension:

| Outcome | Wrapper action |
|---|---|
| Validation/enumeration failure before native create | Ordinary cleanup; no new registration made by this attempt. Existing global registrations remain the installer's responsibility. |
| Native create non-OK, any output handle | Return exact `Error::Native { operation: Create, code }`; never inspect, destroy or retry the output. Exceptionally retain the pinned creation/host tables, independent device reference and runtime bundle. |
| Native create OK/null | Retain the same bundle and report the existing null-context invariant violation, without destruction. |
| Native create OK/non-null | Establish the existing single owner, including callback values and matching host table. Post-create query failures use that owner's normal one-attempt cleanup. |
| Native destroy OK | Release wrapper-owned storage/device/runtime in dependency order. This does not release or unregister externally owned callback targets. |
| Native destroy non-OK | Retain the full wrapper bundle, preserve its native error and never retry. External callback targets remain valid under the installer contract. |

The callback-bearing create-error retention deliberately differs from D005's
ordinary returned-error RAII. The old null-callback evidence does not establish
release of newly registered targets or host-table references on every failure.
Retention is a conservative exceptional cost, not proof of native rollback or
recovery. It may retain a device/runtime until process exit; repeated failing
callback-bearing creates can accumulate retained bundles. Do not add a quarantine
service or claim that retaining the bundle retains external userdata. A later
less conservative policy needs evidence and an explicit contract amendment.

This design avoids both routine successful-path leakage and a context Drop that
prematurely frees globally reachable state. It requires the caller to retain
external state even on an error return. Never infer a safe cleanup window from
an observation that a callback has not fired recently.

## Global diagnostics and native errors

Add the following unsafe methods to both runtime families, with a mutable receiver:

```text
configure_upscaler_debug(DebugLevel, Option<interop::MessageCallback>) -> Result<(), Error>
configure_global_debug_legacy(DebugLevel, Option<interop::MessageCallback>) -> Result<(), Error>
```

The modern method builds `ffxConfigureDescGlobalDebug` with the upscaling effect
constant and passes a null context. It has no provider-ID parameter: the native
descriptor supplies an effect, not an independently selectable provider.
The legacy method builds `ffxConfigureDescGlobalDebug1` with a null context.
Also expose the same explicitly named legacy method on both upscaler families,
passing their live context. This preserves access to the untested live-context
legacy route without guessing it is equivalent to the rejected null-context call.
Do not retry modern as legacy, or legacy as modern, after refusal.

These methods mutate potentially shared native state. A mutable Rust receiver
does not establish exclusive module access. Their safety contract includes the
target lifetimes, cross-context compatibility, no-reentry and common coordination
above, plus safe native continuation/cleanup after success or error. For this
first contract, require affected contexts to be CPU-idle, GPU-complete and free
of executable unsubmitted recordings before configuration; the wrapper does not
wait or discover every sibling. This is a conservative integration precondition,
not a claim that the native setter necessarily records GPU work.
The actual native route must consume the temporary Configure descriptor
synchronously on success and error, without retaining its address. Persistent
callback code/state is separate from that temporary descriptor. Safe release of
the descriptor is an explicit unsafe-call precondition, not inferred from OK.

Every non-OK code is `Error::Native { operation: Configure, code }`; retain the
open code, including the spike's code 2. OK means acknowledgement, not message
delivery, effect isolation, provider application or safe release of old targets.
Both old and new targets must remain valid wherever native reachability remains
possible, including after a rejected or partially applied request.

A live-context legacy error follows D029: preserve the first native failure,
poison dispatch/live queries/Configure and retain one-attempt destruction.
Existing poison rejects before any diagnostic setter FFI. Runtime-global errors
have no live owner to poison and do not invent a registry of poisoned contexts.
The unsafe caller must establish valid shared state and continuation for any
subsequent safe operation, Drop or cleanup; no global error rollback is assumed.
Update `Operation::Configure` documentation to cover these diagnostic operations.

## Binding, safety and implementation checkpoints

Bind both global descriptors/levels, all three debug bits, the DX12 creation
extension, all five callback typedefs and CB aggregate in sys. Preserve native
nullability and constness. No sys symbol loader or public native context handle
is added. The wrapper's interop facade remains additive to existing ownership.

Extend unsafe acquisition documentation for both runtime families to cover
provider-safe checking/visualization flags in construction and memory queries,
and requested debug-view profiles at unsafe dispatch. This accepts no new native
guarantee; the wrapper must not treat prior zero-flag trust as proving new flags.
Callback-specific lifetime/allocator obligations live at each explicit unsafe
installation and persist for all later users. Do not make ordinary construction
an undocumented callback-installation boundary.

Implementation uses the existing concrete pinned chain and shared local/movable
core. Pass the stable optional host table through the private owner to destroy,
with an explicit callback-create failure-retention choice; do not make the generic
owner inspect effect payloads. Update its private safety contract to distinguish
wrapper-owned dependencies from explicitly external callback targets.

Before R03/U04 completion:

1. Assert exact Rust/MSVC layouts, constants and every callback signature,
   including by-value exchange through the production raw CB declaration.
2. Exercise both wrapper families against controlled native callers: default and
   callback chains, paired-group forwarding/omission, identical host table state
   at create/destroy, moves, post-create checks, unknown errors, poison precedence,
   every retention branch and exactly one teardown. Fixture targets outlive
   ordinary Drop and error returns; deliberately dereferencing freed targets is
   not a safety test. Verify portable options and interop platform/trait gates.
3. Verify production debug flag parity and independent frame mapping, faithful
   modern/legacy live/null routing, no fallback and native-code preservation.
   No user callback is wrapped or claimed panic-contained by the library.
4. Run public native callbacks, debug controls, fenced dispatch and cleanup on
   the available selected providers, retaining their observed differences. Cover
   the heap pair with ABI/controlled mapping and record SDK invocation if reached;
   if the provider does not invoke it, retain that native limit explicitly.
   Record the legacy live-context outcome. Neither omission nor code 2 means
   the high-level route can silently disappear from the full-access inventory.
5. Pass relevant current/MSRV, consumers, documentation and native regressions;
   reconcile the coverage inventory. Final package verification remains separate.

The bounded contract is implemented in the shared local/movable core. The
[implementation verification](../release/2026-10-25-callbacks-diagnostics-verification.md) records production ABI exchange, controlled failure paths and public-native
execution. No additional broad research run, callback stress campaign or safe
adapter framework is a prerequisite. Native assumptions remain explicit where
the wrapper cannot enforce them; final release archive verification is separate.
