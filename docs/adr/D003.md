# D003 — Handwrite the first common ABI slice

- Recorded: 2026-09-20
- Status: accepted — explicitly authorized by the maintainer for this slice

**Choice:** Handwrite only the context, return code and structure-tag aliases,
return constants, base descriptor header and its aliases, allocation callbacks,
and five entry-point function-pointer types in `fsr-sdk-sys/src/api.rs`.
The authoritative source is the local SDK `v2.3.0` file
`external/FidelityFX-SDK/v2.3.0/Kits/FidelityFX/api/include/ffx_api.h`.

**Rationale and consequences:** This small boundary remains directly auditable
without generator dependencies or requiring the SDK during ordinary Cargo builds.
Use C-layout structs and nullable unsafe C function pointers; null representation
does not establish SDK acceptance of null callbacks. Return constants use the
native functions' `uint32_t` return type rather than a closed Rust enum.
Rust ABI tests are paired with a standalone MSVC x64 compile-only header check.
The AMD header notice is retained in `crates/fsr-sdk-sys/LICENSE-AMD`.
This does not implement loading, runtime calls or extended descriptors, and does
not select a binding strategy for the full SDK surface.

**Supporting evidence:** [Common ABI verification](../research/records/2026-09-20-exp-common-abi-verification.md),
with current findings in the [API/safety synthesis](../research/api-and-safety.md).
The checks support the tested declarations, not a broader binding or distribution
decision. Retaining the AMD notice was precautionary; its necessity and placement
for this limited slice remain unresolved rather than an accepted licensing policy.
