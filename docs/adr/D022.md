## Naming amendment — 2026-10-18

The maintainer authorized `render_size_for_quality` terminology across both
ownership families and the default/explicit runtime routes, making clear that
these queries calculate provider-reported quality-mode dimensions rather than
read the context's current active size. Only unreleased method names change;
routing, validation, results and native contracts are unchanged.

## Decision

Expose the existing SDK Query descriptors through ordinary `&mut self` methods:

| Runtime (device-backed, pre-create) | Upscaler (live selected provider) | Result |
|---|---|---|
| `upscaler_ratio_dx12(device, mode)` | `upscale_ratio(mode)` | `f32`, positive and finite |
| `upscaler_render_size_for_quality_dx12(device, display, mode)` | `render_size_for_quality(display, mode)` | `Dimensions` |
| `upscaler_jitter_phase_count_dx12(device, render, display)` | `jitter_phase_count(render, display)` | `JitterPhaseCount` |
| `upscaler_jitter_offset_dx12(device, index, phase_count)` | `jitter_offset(index, phase_count)` | `JitterOffsetPixels` |

Movable owners expose the same methods and shared conversions. Portable `query`
contains non-exhaustive `QualityMode::{NativeAa, Quality, Balanced, Performance,
UltraPerformance}` and checked `JitterPhaseCount`, with a positive `i32` constructor
and `count()` getter. No raw enum, pointer, descriptor chain or generic Query is
public in the wrapper. The SDK ratios, render rounding, phase counts and offset
sequence come from the provider; the wrapper never substitutes formulas or
calibrated settings. Calling a helper does not alter options, context, frame or
GPU submission. Jitter retains the native pixel components and signs; the renderer
must apply and report the actual projection jitter.

Runtime utility queries chain a temporary DX12 backend descriptor carrying the
borrowed device, then invoke the existing null-context query path. No override is
added. The default provider at query time may differ from a later context's
provider; live queries use that context's provider. Chain and outputs remain
address-stable for the synchronous call, and the private helper restores `pNext`
before returning. No native or COM reference is independently retained.

## Input and output domains

Render-size queries accept nonzero display dimensions up to `i32::MAX` per axis.
This conservative utility domain also avoids the open provider's float-to-u32
conversion overflowing at the largest u32 display sizes. Returned dimensions
must be nonzero and no larger than display. Smaller results preserve provider
rounding, including odd dimensions.

Phase queries use widths only: nonzero widths at most `i32::MAX` and
`1 <= display_width / render_width <= 16383` in the checked floating-point domain.
The open provider accepts signed widths and casts a floating phase count to i32;
this bound leaves a margin below its overflow boundary. It is an input safety
restriction, not a computed result or universal provider formula. Heights are
ignored. Other providers must safely service this bounded domain under acquisition
trust. Returned counts must be positive i32 values.

Offset queries accept `0 <= index < phase_count`; callers explicitly wrap their
frame counters. Positive counts and the bounded index prevent zero modulo,
negative-sequence inputs and signed index increment overflow in the open helper.
Returned components must be finite; no magnitude or sign adjustment is imposed.
Successful missing/invalid outputs return distinct `InvariantViolation` reasons.
Inputs fail with `Error::InvalidQuery { reason: QueryValidation }` before FFI.
Native non-OK codes remain `Error::Native { operation: Query, code }` and take
precedence over invalid error-path outputs.

## Safety and compatibility

Extend both unsafe runtime acquisition contracts to cover these four utilities:
well-formed known quality modes, bounded dimensions/width ratios, positive signed
counts and bounded indices must be processed safely by the actual selected
providers. The existing synchronous descriptor/output/device non-retention,
bounded writes, common native serialization, live-query GPU compatibility and
ordinary-error continuation assumptions apply, including temporary backend
extensions and every movable use/cleanup thread. This is conditional native trust;
open provider source and fixtures do not prove signed FSR4 internals or universal
provider safety. Loading does not validate these assumptions.

Live queries reject dispatch poison before input checks or native entry. Neither
input errors, native query errors nor inconsistent success outputs set or clear
poison. Runtime queries remain independent of a sibling's poison. Context,
resource, runtime/device retention and terminal cleanup policies stay unchanged.
No new dependencies, SDK pin, effect/backend support, provider override, Configure
surface, quality study, publication or guarantee is introduced. The stronger
acquisition contract belongs to unreleased 0.3.0, not published 0.2.0.

## Verification and basis

Paired Rust/C++ assertions cover the four raw layouts, exact field types, tags and
five quality-mode constants. Host fixtures cover every quality mapping, unusual
provider outputs, numerical boundaries, input rejection without native entry,
missing/invalid outputs, native codes and poison precedence. Windows public
fixtures cover all four owners, device/backend versus live routing, non-retention,
error continuation and poison. A separate native case queries all modes, render
sizes, phase lengths and three offsets for both routes/families, then explicitly
tears down; it records values without requiring cross-provider equality or image
criteria. The native profile also now selects the previously listed M11/M12 cases.
