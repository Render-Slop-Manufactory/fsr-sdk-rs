# D010 — Own the public runtime load error in fsr-sdk

- Recorded: 2026-09-24
- Status: accepted — maintainer requested implementation on 2026-09-24

**Context:** `runtime::LoadError` was a re-export of
`fsr_sdk_sys::loader::LoadError`. Its public variants also named
`libloading::Error`, coupling the high-level error contract to both crates.

**Choice:** Define `runtime::LoadError` in `fsr-sdk` with distinct path,
library, and missing-symbol variants. Map the raw loader error privately.
Retain the path, missing symbol, and original error as a boxed standard error
source. Mark the enum non-exhaustive so future load failures can be added.

**Consequences:** Callers can inspect the same failure categories and use
`std::error::Error::source` for the original I/O or loader cause. The public
type no longer names a `-sys` or `libloading` type. Code relying on the old
type's identity or its concrete `source` fields must adapt; this is an
intentional pre-release public API change. Raw `fsr-sdk-sys` behavior is
unchanged.

**Basis:** [D001](D001.md), [D008](D008.md), the
[high-level runtime](../../crates/fsr-sdk/src/runtime.rs), and the
[raw loader](../../crates/fsr-sdk-sys/src/loader.rs).
