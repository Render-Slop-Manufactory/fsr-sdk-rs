# D020 — Checked per-frame pre-exposure

- Date: 2026-10-14.
- Status: **accepted** under explicit maintainer authorization to implement M11.
- Scope: additive `fsr-sdk` frame input; SDK v2.3.0, existing DX12 profile.
- Relationship: replaces D011's fixed `preExposure = 1.0` restriction in
  development; D014's frame representation and D016's direct-control policy apply.

## Decision

Expose portable `upscaler::common::PreExposure`, also reexported from `upscaler`.
Its private `f32` accepts positive finite values, including positive subnormals,
without clamping or reciprocal conversion. Invalid input returns
`Error::InvalidDispatch` with `DispatchScalar::PreExposure`. `Default` is `1.0`.

`UpscaleDispatch::new` retains its signature and starts with that default.
`pre_exposure()` copies the checked scalar; `set_pre_exposure()` replaces it.
Both ordinary and movable upscalers use the same descriptor mapping, forwarding
the original bits to `ffxDispatchDescUpscale::preExposure`.

The factor reports multiplication already applied to input RGB. The SDK divides
that colour by the factor to recover the original scene signal; the explicit
exposure texture has a separate role. The wrapper does not change pixels, reset
history, enable HDR or alter exposure resources. The renderer supplies matching
content and provider-supported numerical inputs at the unsafe dispatch boundary.
Scalar checks do not establish the provider's complete numerical domain.
Existing resource, GPU lifetime, ordering, poisoning and cleanup rules continue.

## Verification and limits

Portable tests check invalid values, bit preservation and the default. Controlled
Windows fixtures observe exact public-route mapping for both ownership families.
The existing native harness adds three fresh single-frame contexts with matching
RGB factors `0.25`, `1.0` and `4.0`, checking recording, fencing, finite/written
output, device/debug status and teardown. It adds no quality threshold or runner.
Execution status is tracked in the [roadmap](../../ROADMAP.md) and
[Windows native verification](../release/2026-10-15-windows-m11-m14-verification.md),
which passes the deferred fixture/MSRV/ABI and native checks on one configuration.
The [earlier implementation record](../release/2026-10-14-pre-exposure-verification.md)
retains its original execution limits.
