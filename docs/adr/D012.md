# D012 — Keep upscaler options extensible

- Recorded: 2026-09-28
- Status: accepted — maintainer approved the pre-`0.1.0` API change on 2026-09-28

**Context:** `UpscalerOptions` exposed both dimensions as public fields and
derived `Debug`, `Clone`, `Copy`, `PartialEq` and `Eq`. External exhaustive
literals would make adding any setting a construction break. D008 requires a
small value type, checked dimensions and initially zero flags, without requiring
public fields or those traits. D011's public dispatch fields are a separate
contract.

**Choice:** Keep both dimension fields private. Provide
`UpscalerOptions::new(max_render_size, max_upscale_size)` and borrowed getters
returning `Dimensions`. Retain `Debug` and `Clone` for inspection and explicit
reuse; remove `Copy`, `PartialEq` and `Eq`. Preserve today's fixed profile,
checked dimensions and zero creation flags. No builder or `#[non_exhaustive]`
attribute is needed with private fields.

**Rationale:** A constructor can supply defaults for future optional settings
without breaking existing construction calls. Removing `Copy` permits future
owned configuration; removing equality avoids committing the entire
configuration to comparable values without a demonstrated requirement. This
is a deliberate flexibility choice, not a correction of unsound behavior.

**Consequences:** Existing callers replace literals with the constructor and
clone explicitly when reusing options. New mandatory inputs may still require
a breaking API change. Future typed settings need their own supported contract
and defaults that preserve existing behavior. `Dimensions` retains its current
traits; native descriptors, validation, ownership and dispatch behavior are
unchanged.

**Basis:** [D008](D008.md), [D011](D011.md), the
[options](../../crates/fsr-sdk/src/upscaler/common.rs),
[DX12 constructor](../../crates/fsr-sdk/src/upscaler/dx12.rs), and the
[public DX12 example](../../crates/fsr-sdk/examples/dx12_upscale.rs).
