## API coherence amendment — 2026-10-18

The maintainer authorized replacing optional tuning validation with D029's
mandatory parameter-domain checks in `request_tuning`, removing `checked_for`
and the redundant `InvalidConfigure` error. The preflight name now describes
inputs explicitly. These changes affect unreleased APIs only; native trust,
GPU ownership and terminality are preserved. The revised selections follow.

## D042 production amendment — 2026-10-27

U09 replaces item 1's raw pair with portable private-field
`TuningRequest::new(parameter, value)` and one `request_tuning(request)` method on
both families. Full-list construction now precedes the first native mutation in
item 3's renderer example; a later invalid input makes no native change. Native
calls retain their ordered, nontransactional and terminal-error contract.
U08 replaces item 2's combined frame with list/resources/portable parameters and
`validate_upscale_inputs` / `validate_reactive_mask_inputs`; recording rechecks.
The selections below explain the preceding API and retain their native boundaries.
See [D042](D042.md) and the [U09 verification](../release/2026-10-27-tuning-request-verification.md).

## Selected changes

1. Use one `request_tuning(parameter, value)` operation under amended D029.
   Always reject non-finite or outside-domain values with
   `Error::InvalidTuningValue { parameter }` before native entry. Direct enum
   construction and cross-parameter reuse receive the same checks. Accepted bits
   and native `ProviderDefault` remain unchanged; no optional checked constructor
   or public tuning validator remains. Success is acknowledgement, not application.
2. Add safe `validate_dispatch_inputs(&self, &UpscaleDispatch) -> Result<(), Error>` to
   both families. Reuse compulsory dispatch inspection; check poison first;
   call no FidelityFX entry point or mutate eligibility. Temporary DX12 COM
   inspection is permitted, with existing coordination obligations. Validation
   can run before recording/transitions but cannot prove GPU state, content,
   aliasing of backing storage, provider support or submission/completion.
   Dispatch always rechecks, and separate validation is never required for safety.
3. Supply renderer-owned abort/recreate and initial/batched-idle Configure
   examples. Retain the old owner until failed/abandoned recordings are
   invalidated and earlier submissions complete. Destruction remains consuming
   and single-attempt; fresh context history starts reset. Apply desired settings
   in an established idle interval. Each request validates before its own native
   call; a later validation error leaves earlier requests acknowledged and the
   context usable. A native error is terminal. Multiple calls have no atomicity/rollback.
4. Prepare an opt-in optimized native startup-query timing profile. Measure
   default and explicit-provider sequences before selecting enumeration caches
   or sessions. Fresh membership/identity policy and D028 method signatures stay
   unchanged. Missing Windows/native equipment prevents actual measurement here.
5. Correct stale mask/provider-selection Rustdoc. Refine D030 to propose the
   corresponding optional generator preflight and explicit probe/recovery limits.
   D030 remains proposed and unimplemented.

## Boundaries and alternatives

These changes address earlier diagnosis and deterministic recovery. They do not
make native failure or successful-recording abandonment reusable, permit
in-flight Configure, or prove generator capability. Those stronger changes need
provider-specific mutation/rollback/ordering evidence. No recording/fence token,
prepared-resource cache, provider session or second Configure method is added.

The earlier optional tuning helper did not retain its parameter association.
The amendment removes it in favour of compulsory operation-boundary checks.
Optional dispatch-input preflight remains a distinct setup operation; dispatch
always repeats inspection. They
preserve published frame constructors and dispatch signatures. Windows/DX12
isolation remains binding under [D031](D031.md).

## Verification

Check every tuning domain and original accepted bits through the actual request
boundary, including direct construction, cross-parameter reuse, no native entry
on validation errors and poison precedence. Compile portable request enums and
both public ownership families; reject reintroduction of the checked constructor. Exercise both public
preflight families against controlled COM errors, required inputs, no-native-call
and reference-retention checks, changed metadata after successful preflight and
both poison origins. Compile all renderer examples as downstream consumers.
Separate host execution, Windows compilation, Windows fixture execution and
actual-provider measurements. Native timings are observations, not a speed gate
or evidence that a cached selection would remain valid.

[Implementation checks](../release/2026-10-18-upscaler-ergonomics-verification.md)
record passing local CI/MSRV and Windows compilation separately from unexecuted
Windows preflight fixtures and native startup measurements. The later
[coherence checkpoint](../release/2026-10-18-api-coherence-verification.md) verifies
the amended tuning/input/query names and domains, including isolated development
packages; Windows fixture/native execution and startup timings remain unrun.
