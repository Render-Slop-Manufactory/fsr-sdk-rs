# D009 — Leave public error categories open for extension

- Recorded: 2026-09-24
- Status: accepted — maintainer agreed on 2026-09-24

**Context:** `fsr-sdk::error` exposes `Error`, `Operation`, and
`InvariantViolation` as public enums. The current API has creation and
destruction failures; later Query, Configure, Dispatch, and wrapper validation
may require additional cases. Without an explicit extensibility boundary,
downstream crates can match every current variant and fail to compile when a
variant is added.

**Choice:** Mark all three enums `#[non_exhaustive]`. Keep the existing variants,
fields, native `u32` code representation, and error behavior unchanged. Do not
mark individual variants non-exhaustive in this change.

**Consequences:** Downstream matches on each enum need a fallback arm. Adding
the attribute can require existing Git consumers with exhaustive matches to
update their code; doing it while the API is early keeps that adjustment small.
Known variants remain constructible by downstream code, and exhaustive matching
inside this crate remains possible. Future variants can be added without
breaking downstream matches that include a fallback arm, but changing fields
of an existing variant remains a separate compatibility decision. A fallback
arm does not replace handling known failures deliberately.

**Basis:** The current [error implementation](../../crates/fsr-sdk/src/error.rs),
the future API scope in [D008](D008.md), and the
[Rust Reference's `non_exhaustive` rules](https://doc.rust-lang.org/reference/attributes/type_system.html#the-non_exhaustive-attribute).
