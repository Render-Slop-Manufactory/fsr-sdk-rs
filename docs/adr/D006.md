# D006 — Curate ABI slices and permit reviewed generated bindings

- Recorded: 2026-09-22
- Status: accepted — handwritten-by-default policy with reviewed generated
  exceptions explicitly selected by the maintainer

**Context and choice:** Resolve the broader binding policy left open by D003
without replacing its accepted common ABI slice. Handwritten declarations are
the default for deliberately selected `fsr-sdk-sys` ABI slices. Generated
bindings may be used where their maintenance and review benefits justify them,
including preview, volatile or peripheral surfaces. After explicit review,
generated bindings may also remain the implementation of first-class supported
ABI. Support promotion does not require manual retranscription, and size alone
does not automatically determine the binding method.

Classify concrete ABI slices, not whole effects. Upstream maturity, raw ABI
coverage, safe-wrapper support and verified runtime compatibility are separate
properties. Neither a handwritten create descriptor nor generated raw access
establishes support for an entire effect. Both methods require deliberate API
selection and the same ABI correctness standard.

**Generation and integration:** Run `bindgen` only during repository maintenance.
Format, review and check generated source into the repository. Ordinary consumer
builds require neither FidelityFX headers, Clang nor bindgen. Generation is not
a Cargo build-time acquisition mechanism and introduces no implicit downloads.

For each supported target configuration, each included native ABI entity has
one canonical Rust representation. Generated slices reuse existing common and
backend types through imports, reexports or appropriate aliases. Use bounded
allowlists and blocklists to avoid duplicate definitions and unintended
transitive system bindings; verify the resulting type identity as well as layout.
Generated declarations must preserve D004's explicit runtime-loading boundary:
do not introduce direct native linking or a parallel entry-point access mechanism
as an incidental consequence of generation.

Version-control the generation configuration and sufficient provenance to
reproduce the output: SDK revision and input headers, bindgen and Clang versions,
target, relevant defines, include/toolchain inputs, selection rules and formatting
or deterministic post-processing. Do not make untracked manual fixes to generated
files. Preserve applicable upstream notices and inspect transitive material under
the existing contribution and packaging rules. Regeneration comparison may be
added to CI when a generated slice exists.

**Verification:** Apply equivalent relevant checks to handwritten and generated
ABI: sizes, alignment, field offsets and types, integer widths, calling
conventions, callback signatures/nullability, tags, versions and platform gates.
Compare against the pinned native headers using independent native checks;
successful generation, reproducible output and generated layout tests alone do
not establish correctness. The checks may differ mechanically, but generated
surfaces do not receive a lower correctness standard.

**Rationale:** Small handwritten slices make deliberate modeling and audit easy;
generation can reduce mechanical transcription and maintenance work for suitable
surfaces. Neither method is inherently a higher support or quality tier. Review
and verification establish confidence. Maintainer-time generation keeps SDK and
generator tooling out of consumer builds and exposes changes to normal review.

**Consequences and limits:** The raw crate may contain clearly identified
handwritten and generated modules. Changes to an existing slice's method require
explicit review, including public paths, type identity and compatibility; do not
silently replace a curated slice. The safe crate remains curated independently
of raw binding origin. Public raw bindings still require documented coverage
and compatibility expectations even when no safe wrapper exists.

This decision introduces no bindings, tooling dependency, permanent module layout
or new effect-support commitment. Generate nothing until a concrete slice
warrants it. D005's accepted lifecycle contract is unchanged; this binding policy
does not resolve additional native safety questions.
