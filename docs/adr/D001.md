# D001 — Separate raw bindings and ergonomic wrappers

- Recorded: 2026-09-16
- Status: accepted — existing project baseline, not a new approval

**Context and choice:** Wrap AMD's official SDK using `fsr-sdk-sys` for the native
ABI and loading, and `fsr-sdk` for ergonomic ownership, validation, and errors.
Keep both independent of a particular engine or renderer.

**Rationale:** Raw ABI details should remain auditable without forcing consumers
to reproduce pointer handling and lifetime management. This wraps AMD's
implementation rather than reimplementing FSR.

**Consequences:** ABI compatibility takes precedence over Rust naming preferences
in the raw layer. Safe abstractions must establish their invariants rather than
hide native obligations. The workspace and module scaffolding exist; native
bindings, loading, and safe wrappers are not implemented yet.

**Basis:** [Project scope](../../SCOPE.md), [workspace manifest](../../Cargo.toml),
[raw crate](../../crates/fsr-sdk-sys/src/lib.rs), and
[wrapper crate](../../crates/fsr-sdk/src/lib.rs).
