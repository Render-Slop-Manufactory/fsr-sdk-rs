## Context

M10 adds provider metadata and resource/memory planning to the existing upscaler.
The [source review](../research/records/2026-10-12-src-m10-dx12-query-safety.md)
finds synchronous open-provider query paths, but cannot establish universal
closed-provider name validity, non-retention or in-flight GPU compatibility.
It recommends a conditional extension of the existing unsafe acquisition
boundary. A passing native spike would not prove those universal properties.

## Decision

Add five safe methods, all requiring `&mut self` and returning `Result<T, Error>`:

| Owner | Method | Result |
|---|---|---|
| Runtime | `upscaler_providers_dx12(device)` | `Vec<ProviderInfo>` |
| Runtime | `estimate_upscaler_memory_dx12(device, &options)` | `GpuMemoryUsage` |
| Upscaler | `provider()` | `ProviderInfo` |
| Upscaler | `resource_requirements()` | `ResourceRequirements` |
| Upscaler | `gpu_memory_usage()` | `GpuMemoryUsage` |

Movable owners expose the same methods through shared private descriptor/result
functions, RuntimeState invocation and NativeContextOwner/UpscalerCore. Retain
existing family/trait boundaries. No public generic Query, mutex, GPU submission
or GPU wait is added. Results live in portable `query`; native methods retain
Windows/DX12 gates. Fields are private, with getters. ProviderId has equality,
hashing and diagnostic Debug, but no public numeric constructor/accessor or
semantic-version/order guarantee. Names are immediately owned, using lossy UTF-8
conversion. Memory getters name bytes. ResourceFlags preserves the full native
u64, exposes known input flags and unknown bits, and separates required/optional.
Reported requirements do not expand the supported dispatch profile.

## Conditional native safety contract

Both unsafe `load_unchecked` contracts explicitly require the actual selected
providers to handle the wrapper's well-formed queries safely:

- Consume descriptor chains, outputs and borrowed devices synchronously without
  retaining their addresses; populate outputs on success and respect capacities.
- Return readable NUL-terminated names valid through immediate copying under
  shared native serialization. Coordination includes the entire count/fill/copy
  operation, siblings, external native users and implicit cleanup.
- Safely handle the nonzero u32 option dimensions in memory V2, including internal
  arithmetic, and the wrapper's zero creation flags. D008 construction trust is
  not assumed to prove this distinct query path.
- Support live queries in every GPU state permitted by D011, including work in
  flight, under the shared CPU coordination. Hidden native workers must preserve
  these guarantees. Application locks do not replace GPU completion.
- Preserve a usable live context after an ordinary query error. Reject live
  queries after dispatch poison before entering native code.

These obligations persist for all derived objects and, for movable owners, every
subsequent use/cleanup thread under D013. They are accepted caller-established
native trust, not newly proven AMD guarantees. If a configuration cannot uphold
them, the new acquisition contract must not be used. The wrapper enforces storage,
descriptor, ownership and eligibility invariants; it cannot validate a dangling
name pointer or prove native non-retention/GPU compatibility.

## Enumeration and errors

Enumeration is a bounded count/fill observation, not a transaction or promise of
completeness. Growth may truncate; shrinkage returns fewer slots. Request IDs
and names together, use checked representable allocation and initialized arrays,
read only returned slots and copy before another native operation. Return an
empty vector on zero count. Do not retry indefinitely or claim stable selection.
Pre-create memory describes the then-default provider and is not a reservation,
construction validator or promise of later provider identity.

Preserve every non-OK code, including unknown codes, as Error::Native with
Operation::Query. Do not interpret error outputs. Successful null names, zero
live IDs and counts above supplied capacity are native invariant errors.
Enumeration allocation failures have a separate error. Zero memory values,
unknown resource bits and overlap are not rejected by invented semantic rules.
Query errors never clear dispatch poison and do not introduce dispatch poison;
continuation rests on the explicit native trust above. Runtime queries remain
available independently of one sibling's dispatch poison, under family-wide
coordination. Terminal teardown and D005 retention stay unchanged.

## Alternatives and compatibility

Unsafe query methods with `_unchecked` names would reserve ordinary names for
future safe wrappers if query trust were rejected. GPU-quiescent measurement
alone would not establish arbitrary-provider safety. The selected acquisition
trust permits ordinary safe method names and avoids duplicating public variants.
Provider override and quality/jitter helpers remain separate work.

The method additions are additive; strengthening unsafe acquisition obligations
is a public safety-contract change. This is unreleased source work and must not
be described as the published 0.2.0 contract. On 2026-10-13 the maintainer selected
M10 for `fsr-sdk 0.3.0`, paired with `fsr-sdk-sys 0.1.2` for its additive raw
declarations. The minor wrapper release identifies the stronger unsafe acquisition
contract. [Release preparation](../release/0.3.0-preparation.md) remains open to
further additions; final package verification and publication are separate.

## Verification

Verify the additional handwritten ABI against pinned headers with independent
Rust/C++ assertions. Controlled queries cover device/options forwarding,
count/fill growth/shrinkage, copied names, invalid success outputs, unknown masks,
native codes and poison eligibility. Downstream checks cover portable results,
feature gates and both families. Windows native verification executes all five
public methods for both families and then existing dispatch regressions. Source,
compilation, fixtures and actual GPU execution must be reported separately.

The [2026-10-12 Windows checkpoint](../release/2026-10-12-windows-m10-sdk-verification.md)
passed those checks on one GPU/driver/provider configuration. It completes M10's
unreleased-source checkpoint without proving universal provider safety or
selecting a release at that time. The later selection above does not change the
historical verification inputs or imply final release-package checks.
