# Complete 0.2.0 release verification — 2026-10-10

## Result and release scope

**The complete release passed the recorded local checks:** `fsr-sdk 0.2.0`
with `fsr-sdk-sys 0.1.1`, including the optional `movable` family. The maintainer
explicitly superseded the earlier exclusion of movable from `0.2.0` on
2026-10-10. [D013](../adr/D013.md#release-scope-amendment--2026-10-10),
[D014](../adr/D014.md#combined-release-scope-amendment--2026-10-10), manifests,
READMEs, Rustdoc, changelog and roadmap now reflect that selection.

This verifies actual source and Cargo-generated archives from this checkout,
without the earlier M9 source projection. The
[original M9 report](2026-10-10-m9-verification.md) remains evidence for its
different candidate. **Nothing was committed, pushed, tagged or published.**
The user-facing docs are prepared for the release, with `0.2.0` links and usage;
hosted crates.io/docs.rs/GitHub release availability is not claimed by this check.

The [summary](2026-10-10-0.2.0-release-verification/summary.json) retains 64
package/source/consumer gates, including 12 expected compiler failures. Native
checks passed on the configuration below. The publication dry-run succeeded in
sys-then-wrapper order, regenerated identical archives and explicitly aborted
both uploads. No observed code, fixture or native failure blocks this release
within its existing support and unsafe-contract boundaries.

## What changed

- Wrapper version `0.2.0`; raw crate and wrapper's raw dependency `0.1.1`.
  Only these two workspace versions changed in the lockfile. SDK pin, selected
  ABI and third-party dependency versions/checksums are unchanged.
- Keep the implemented movable feature, types, consumer example and tests in
  the actual release. Local types remain `!Send + !Sync`; movable types remain
  `Send + !Sync`, with no family conversions or internal synchronization.
- Include movable in the Windows-target docs.rs build configuration. Update
  `0.1.0` frame literals to the public `UpscaleResources` / `UpscaleDispatch`
  constructors in current usage documentation, and repair stale GPU-check status.
- Add an isolated native regression for `Native(0.35)` through the actual public
  movable path after thread handoffs. It shares the existing disabled test's
  equipment, synchronization and cleanup checks; no production behavior changed.
- Shorten the repository README to SDK scope, current capabilities, installation,
  integration, optional movable ownership and a contributor entry point. Retain
  its intentional first-person introduction and project branding. The authorial
  voice is not a private-data or secret finding. The previously checked Rust
  snippet is unchanged.
- Show SDK feature coverage in the README and make complete SDK coverage the
  explicit long-term goal. Replace release-relative planning with rolling queues
  in [ROADMAP.md](../../ROADMAP.md); move completed checkpoints to
  [roadmap history](../ROADMAP_HISTORY.md). These documentation changes establish
  no additional native support or new accepted API contracts.

## Reproduction and publication boundary

Use PowerShell 7, the recorded stable/MSRV toolchains, cached declared dependencies
and an x64 Visual Studio developer shell for native execution. Run from repository
root; the verifier and native stages use `target` and never upload.

```powershell
python docs/release/2026-10-10-0.2.0-release-verification/verify-release.py
./tools/check-movable-api.ps1 -Stage target/release-020-api-controls
./crates/fsr-sdk/tests/native/run.ps1 -Mode movable -Native -Stage target/release-020-native-source-unrestricted
$previousCargoHome = $env:CARGO_HOME
$env:CARGO_HOME = (Resolve-Path target/release-020-20261010/isolation-final/cargo-home).Path
./crates/fsr-sdk/tests/native/run.ps1 -Mode movable -Native -Stage target/release-020-native-artifact -TestManifest target/release-020-20261010/isolation-final/packages/fsr-sdk-0.2.0/Cargo.toml
./crates/fsr-sdk/tests/native/run.ps1 -Mode m9 -Native -Stage target/release-020-m9-artifact -TestManifest target/release-020-20261010/isolation-final/packages/fsr-sdk-0.2.0/Cargo.toml
$env:CARGO_HOME = $previousCargoHome
cargo publish --dry-run --workspace --locked --allow-dirty --target-dir target/release-020-20261010/dry-run --config net.retry=0
python docs/release/2026-10-10-0.2.0-release-verification/collect-release.py
python docs/release/2026-10-10-0.2.0-release-verification/audit-release.py
```

Use a fresh checkout/stages for reproduction. `--resume` preserves completed
checks when repairing the verifier environment; it must not be used to reuse
passes after changing tested source. Existing partial stages and unsuccessful
checks are retained. The [setup summary](2026-10-10-0.2.0-release-verification/summary.json)
records sandbox temporary-file/cache and registry-network restrictions plus two
verifier setup corrections. All blocked sandbox runs stopped before GPU children;
there were no failed native acceptance children, retries or relaxed assertions.

After committing the reviewed source, the maintainer can publish sys `0.1.1`
before wrapper `0.2.0`, and create the GitHub `v0.2.0` tag/release from that source.
Real registry authentication/server acceptance and hosted docs were not tested.
Existing GBV timeout and the original failed sharpening-effect experiment remain
unchanged. No second GPU/provider, sanitizer, broad image-quality/performance
claim or outstanding-GPU-work transfer guarantee is added. Movable's native
compatibility, hidden activity, termination and common-domain coordination
