# Temporal calibration: compact evidence

The [experiment record](../2026-10-11-exp-v01-verification-calibration.md)
contains the actual protocol, equipment, failed attempts, results and limits.
This is diagnostic calibration, not V01 acceptance.

On 11 October 2026 the maintainer selected compact evidence retention. Complete
raw frames, verbose per-frame analyses, repeated source snapshots and exported
logs were removed from the repository after their inventory was checked. A new
implementation of the compact pooling exactly reproduced the recorded arm and
control measurements before removal. Original numerical findings and failed
attempt statuses have not changed.

| File | Purpose |
|---|---|
| `attempts.json` | Original attempt identities, dates and outcomes |
| `checks.json` | Commands, expected markers, execution and case outcomes for all seven attempts/checks |
| `inputs.json` | Primary source and native input SHA256 identities |
| `protocol.json`, `jitter.json`, `jitter.txt` | Original frozen geometry, controls, quantization and exact jitter |
| `summary.json` | Primary independent audit outcome, repeat/reset measurements and region summaries |
| `diagnostic-summary.json` | Pooled point/area/temporal/leakage/control measurements and native log cross-checks |
| `contact-sheet.png` | Selected visual examples; not a full-precision output fixture |
| `reanalysis-provenance.json` | Later attempt-1 reanalysis identity; attempt 1 remains failed |
| `package-inspection.json` | Historical local package inspection, not publication |
| `retention.json` | Dated removal scope and explicit reanalysis limits |
| `artifacts.json` | Identities of these compact files |

Full offline image reanalysis of the original attempts is no longer available
from this checkout. Hashes identify bytes but do not reconstruct measured GPU
outputs. Synthetic inputs are generated by the retained test code and protocol;
GPU measurements require a new run with the stated SDK/equipment prerequisites.
Drivers, hardware or SDK providers can change the results of that new run.

Current reproduction, with an existing NumPy-equipped Python:

```sh
python tools/verification/run.py run experiment-temporal-calibration --native --sdk-root external/FidelityFX-SDK/v2.3.0/Kits/FidelityFX --adapter-index 0
```

The current responsible names and the original historical namespace are recorded
in the parent report. New runs independently validate every input and output
before disposing of bulk files. For a specific local diagnosis, pass
`--retain-diagnostics`, then use the independent `temporal_calibration.py audit`
command on that local attempt. Exports remain compact. Keep such diagnostic data
under ignored `target/` only as long as that diagnosis needs them.

The SDK code, generators and analyses remain in the ordinary source tree with
their existing root/crate licence texts. There is no separate data archive or
automatic evidence download.
